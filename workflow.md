The Master Demoz End-to-End Operational BlueprintThis document sets forth the complete, production-grade technical and operational workflow for Demoz. It maps out every interaction across all four user classes, identifying core system challenges, security vulnerabilities, and the exact software countermeasures built into the architecture.1. Platform Super Admin Workflow (Us / Demoz Operators)This workflow defines how we manage system health, resolve gateway bottlenecks, provision infrastructure, and monitor platform-wide multi-tenancy.Step-by-Step Chronological JourneySystem Provisioning & Cluster Initialization: We deploy the backend NestJS modular monolith inside isolated Docker containers across a multi-availability zone AWS setup. We configure a production-grade PostgreSQL instance running with PgBouncer to manage high-volume connection pooling.Telecom USSD Gateway Binding: We establish a dedicated connection with telecom providers (Ethio Telecom and Safaricom) via an aggregator like Africa's Talking. We route the dedicated shortcode to hit our public, load-balanced endpoint: [https://api.demoz.com/v1/attendance/ussd](https://api.demoz.com/v1/attendance/ussd).Chapa Escrow Engine Configuration: We establish a verified corporate account with Chapa. We configure the system's core webhook receiver (/v1/finance/webhooks/chapa) with an explicit secret key to verify that incoming payment notifications are cryptographically signed by Chapa's servers.AI Processing Queue Deployment: We spin up an isolated Redis cluster dedicated exclusively to BullMQ. We configure two core processing queues: payroll-processing-queue and ai-anomaly-detection-queue. This separation ensures heavy analytical work never impacts user dashboard interactions.Multi-Tenant Subscription Auditing: We access our internal Super Admin Control Panel to monitor metrics across all active corporate tenants. We review real-time infrastructure logs, track total active seat metrics, flag delinquent enterprise subscribers, and audit system-wide transaction success rates.Security Defenses & Engineering SolutionsProduction ChallengeSystem VulnerabilityThe Demoz Software SolutionData Bleeding Between Corporate ClientsA developer forgets to add a where clause in an update query, exposing Company A's salaries to Company B's HR.Prisma Runtime Query Interception: We implement a database-level global extension. The extension intercepts every outgoing database read and write query, automatically injecting a mandatory tenantId = active_tenant_id filter. Data isolation is mathematically guaranteed at the engine level.Webhook Spoofing (Fake Chapa Confirmations)An attacker finds the payment webhook URL and sends fake HTTP POST requests to mark invoices as paid without sending real money.HMAC-SHA256 Cryptographic Verification: Our NestJS webhook endpoint rejects all incoming requests that lack an X-Chapa-Signature header. The system computes a local SHA256 hash using the raw request body and our private Chapa webhook secret key, comparing it to the header signature. If they do not match exactly, the system drops the connection and alerts security.2. Client Company Owner Workflow (The Tenant Admin / The Checker)This workflow maps out how a corporate business owner subscribes to Demoz, configures their company, establishes internal access control, and executes multi-million Birr payrolls securely.Step-by-Step Chronological JourneySelf-Service Registration & Tenant Generation: The Owner lands on the Demoz web portal. They sign up with their corporate email, corporate phone number, and official business registration data. The backend creates a new UUID in the Tenant database table and assigns them a unique, 4-digit companyCode (e.g., 4812) used for USSD identification.Mandatory Two-Factor Authentication (2FA) Setup: Upon initial login, the Owner is blocked by a security gate forcing them to configure 2FA. The system generates a secure Time-based One-Time Password (TOTP) secret key, renders a secure QR code on the dashboard using WebCrypto APIs, and requires a verification input token before granting dashboard access.Workspace Topography & Geofence Binding: The Owner navigates to Settings -> Branches. They input their corporate offices, manufacturing plants, or construction sites (e.g., "Bole Lemi Factory Pool A"). They pin the exact location coordinates on the embedded map interface, setting an explicit maximum allowed meter radius (e.g., 150m).Subscription License Allocation: The Owner selects their operational tier based on employee headcount. The system evaluates their seat capacity constraints. When the corporate payment is processed, the system updates maxEmployees and sets subscriptionExpiresAt to exactly 30 days out.The Final Payout Authorization Window: On payday, the Owner receives a secure notification stating that payroll is finalized and audited. They log into the secure dashboard, review the compiled gross-to-net financial sheet, view the automated AI Fraud Risk Score, input their active mobile 2FA code, and click "Execute Chapa Disbursement."Security Defenses & Engineering SolutionsProduction ChallengeSystem VulnerabilityThe Demoz Software SolutionInternal Fraud (The Rogue HR Admin)An HR employee modifies a bank account field or adds a fake worker to the roster to siphon corporate funds.Enforced Maker-Checker RBAC Guards: We implement an absolute Role-Based Access Control (RBAC) guard setup. The HR Admin role has "Maker" privileges (can compile and view drafts) but lacks access to the disbursement engine. The payment pipeline strictly validates that the executing JWT contains role: 'OWNER' and matches the authorized 2FA session token.Replay Attacks on Bank PayoutsA network dropout happens mid-transfer. The Owner clicks "Pay" again, accidentally sending duplicate salary payments to employees.Cryptographic Idempotency Tokens: Every bulk payroll execution forces the system to construct a deterministic, unique identity string (tx_ref) for the batch (e.g., tenantId_payrollRunId_month_year). This unique token is hardcoded into the header of the Chapa bulk transfer payload. If Chapa receives the exact same token a second time, it rejects the transaction, preventing duplicate payouts.3. HR Admin Workflow (The Corporate Maker)This workflow outlines how the HR department manages daily operations, updates the employee roster, audits daily logs, and handles local compliance calculations.Step-by-Step Chronological JourneyCompliance-Locked Workforce Onboarding: The HR Admin adds workers to the system. For individual entries, they use a multi-step form; for bulk operations, they upload an Excel sheet. The database model requires a valid name, active phone number, base salary, and a 12-digit Fayda National Identification Number.Issuing Secure USSD Credentials: When a frontline worker is added, the system generates a unique, pseudo-random 4-digit PIN code. The HR Admin prints a physical ID card containing this passcode or delivers it securely to the employee, prompting them to dial in via feature phones.Reviewing the Daily Anomaly Panel: Every morning, the HR Admin reviews the Attendance Flags interface. Instead of sorting through thousands of clean logs, the UI surfaces entries flagged as isAnomaly: true. The HR Admin views the detailed flag reasons (e.g., "Geofence Breach: 2.4 Kilometers Away" or "USSD Input Velocity Flash").Triggering the Background Payroll Process: At the end of the month, the HR Admin clicks "Run Payroll Calculation." The Next.js dashboard targets the NestJS endpoint /api/v1/payroll/run. The server immediately returns an HTTP status code 202 Accepted to keep the UI smooth, while a background BullMQ worker processes the heavy calculations.Finalizing the Draft Sheet for Review: The background worker iterates through the company's active roster using database streaming cursors. It computes the progressive Ethiopian income tax brackets (0% to 35%), subtracts the mandatory 7% employee pension contribution, maps the 11% employer liability, and aggregates position allowances into a draft payroll sheet for the Owner's review.Security Defenses & Engineering SolutionsProduction ChallengeSystem VulnerabilityThe Demoz Software SolutionMemory Exhaustion During Bulk UploadsHR uploads a CSV containing 5,000 workers. The server tries to parse and insert all rows at once, running out of RAM and crashing the platform.Transactional Stream Chunking: The file upload pipeline uses a memory-efficient stream parser. It breaks the data file into chunks of 100 rows. Each chunk runs inside an explicit database transaction (prisma.$transaction). If a row fails validation, that single chunk rolls back, and the system continues processing the remaining lines while generating an error report for the user.Stale-Data CalculationsHR modifies an employee's salary mid-month, but the payroll engine uses cached data, resulting in incorrect payout values.Dynamic Cache Invalidation with Key Busting: Whenever an employee record is modified, the HrModule hooks into our Redis server and executes a precise cache deletion command against the key pattern tenantId:employeeId:profile. The payroll engine is forced to pull fresh data directly from PostgreSQL, keeping financial calculations accurate.4. Employee Workflow (The Frontline Workforce)This workflow defines the day-to-day experience of the actual workers tracking time through our two distinct channels: smartphone native apps and offline USSD setups.Flow A: The Native iOS / Android Smartphone UserBiometric Device Handshake: The employee downloads the Demoz Mobile App built via Expo. They log in once using their registered mobile number and PIN. The application securely saves their JWT inside the device's hardware enclave using expo-secure-store and prompts them to activate FaceID or TouchID for seamless future access.Geofenced Clock-In Verification: Upon arriving at the workplace, the employee opens the application and taps the central "Clock In" control. The application invokes expo-location with high-accuracy settings, captures the device's latitude and longitude coordinates, and fires an API request containing the location data to the backend.The Offline Tracking Contingency: If the employee attempts to check in inside an area with poor cellular service, the application catches the network failure. It securely stores the attendance payload locally along with a hardware-verified, tamper-proof timestamp. A persistent background sync task continuously retries the request until connectivity is restored.Self-Service Payroll Portal: Once payroll is processed, the worker receives a push notification. They navigate to the Wallet view, authorize access via biometrics, inspect their historical gross-to-net pay distribution breakdowns, and export a cryptographically sealed PDF copy of their payslip.Flow B: The Offline Feature-Phone User (USSD Network Engine)Initiating the Shortcode Request: A frontline worker with a basic feature phone dials the Demoz enterprise shortcode: *251*4812# (incorporating the unique companyCode).Stateless Menu Processing: The telecom gateway sends an HTTP POST request to our UssdController.
